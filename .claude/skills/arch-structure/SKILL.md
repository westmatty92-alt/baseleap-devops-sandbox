# Architect · Repo Structure & Scaffold

The scaffold is the foundation both build lanes branch from. It must compile on day one, and its folders must make file ownership obvious — so two agents in two worktrees never edit the same file.

## 1. Layout (house default — single Next.js app, `src/` layout)

```
src/
  app/                    ← routes & pages                     (frontend lane)
    (app)/…               ← signed-in screens
    embed/…               ← GHL-iframe entry points (if the PRD has embedded modules)
    api/…/route.ts        ← route handlers                     (backend lane)
    theme.css             ← GENERATED from DESIGN.md (designer)
  components/             ← UI components; components/ui = shadcn primitives   (frontend lane)
  hooks/                  ← app-level client hooks (not API hooks)             (frontend lane)
  lib/
    server/               ← server-only modules: db, auth, integrations (backend lane)
                             each file starts with `import 'server-only'`
    api/
      generated/          ← GENERATED by Orval from docs/openapi.yaml:
                             typed fetchers, TanStack Query hooks, Zod schemas, MSW mocks
      fetcher.ts          ← the one hand-written piece: base URL, auth header, problem+json errors (frontend lane)
    shared/               ← pure helpers used by both (architect owns; changes = contract question)
  types/
    database.ts           ← GENERATED: supabase gen types typescript
  mocks/                  ← MSW browser/server setup wiring the generated handlers (frontend lane)
supabase/migrations/ · supabase/tests/rls/ · supabase/seed.sql   (architect)
DESIGN.md (brand contract) · design/mockups/ (designer) · orval.config.ts (architect)
docs/  PRD.md · user-stories.md · metrics-spec.md · user-flows.md · design-specs.md · tokens.json (GENERATED) ·
       design/screens/ · architecture.md · SECURITY_MODEL.md · openapi.yaml · decisions/
```

Rules:
- **Business logic lives in `src/lib/server/`, not in route handlers or components.** Handlers parse input, call a server module, shape the response. That keeps logic testable and keeps the frontend lane out of it.
- **Generated code is never edited by hand** and never duplicated: `src/lib/api/generated/` (Orval, from the contract — template `templates/orval.config.ts`) and `src/types/database.ts` (Supabase). If a type is wrong, the contract or migration is wrong — fix that and regenerate. No hand-written `packages/shared/types.ts`, no hand-written API hooks.
- Lane ownership goes into `docs/architecture.md` ("Lane ownership") — the orchestrator copies it into each build step's owned `files`.
- Monorepo (Turborepo workspaces) only when there's a second deployable, with a decision record.

## 2. Scaffold the skeleton

1. Create the app with the framework's own generator (non-interactive flags), TypeScript strict, ESLint.
2. Add the house dependencies only: Supabase client (`@supabase/ssr`), Tailwind + shadcn base, TanStack Query, `zod`, `react-hook-form`, Orval + MSW (dev), test runner (Vitest + Testing Library) and Playwright (QA configures it later).
3. Scripts in `package.json` — the build lanes and CI rely on these exact names:
   `typecheck` · `lint` · `test` · `build` · `gen:types` (Orval + Supabase types) · `mock` (Prism on the contract) · `db:test` (migrations + RLS tests against the preview branch: `supabase db push --db-url "$SUPABASE_PREVIEW_DB_URL" && supabase test db --db-url "$SUPABASE_PREVIEW_DB_URL"`, with the Supabase CLI as a dev dependency; tests are pgTAP files under `supabase/tests/`). The script refuses to run when the URL contains the production project ref.
4. A `GET /api/health` route returning `{ status: "ok", version }` — devops and QA depend on it.
5. Placeholder pages for each screen in the design spec's inventory (title only) so routes exist for both lanes.
   Keep the designer's generated `src/app/theme.css` (from `DESIGN.md`) and import it from the global stylesheet; never overwrite or hand-edit it.
6. Commit to the `staging` branch as `STEP <id>: scaffold` — lanes are created from this commit after Gate 2.

## 3. Prove it compiles (the step's verify)

```
npm ci && npm run gen:types && npm run typecheck && npm run lint && npm run build && npm run db:test && node scripts/check-mock.mjs
```
All must exit 0 on a clean checkout. `check-mock` starts Prism on the contract, calls a GET, and stops it, which proves the frontend can work against mocks on day one. A skeleton that only builds on your machine isn't a skeleton.

## 4. Keep it small

No feature code, no speculative abstractions, no "utils" grab-bag. Every folder exists because a screen, an operation or a migration needs it. If you find yourself writing business logic, stop — that's a build-lane step.
