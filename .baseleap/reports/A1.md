### Decisions made (all `proposed`)
- **0001** House stack, no deviations; PWA = manifest + a hand-written service worker that caches only the offline page.
- **0002** Sign-in: one email with a link **and a 6-digit code**. Typing the code inside the installed iPhone app answers **OQ-10 (option A)**. Users are pre-provisioned, sign-ups are off, the server decides listed or not, and every outcome looks the same, with rate limits and a 1.5 s minimum response time. The confirm link needs a button press, so email scanners can't use it up. Removal stops data access at once (RLS) and bans the auth user. Sign-in is Server Actions plus one route handler, outside `/api`.
- **0003** OQ-3: option B (Supabase built-in mail) **is not viable**: 2 emails/hour, and only to Supabase org team addresses. Recommend custom SMTP on Resend Free.
- **0004** Tenant `org_id` everywhere. **OQ-9 answered:** e2e runs in a separate `is_test` org on every environment, so it never shows on Northside's board (AC-006.6). Tests sign in with an admin-generated token (service role in CI only), and the app has no test login path.
- **0005** Column rules, `version` concurrency, idempotency, audit and events enforced by DB triggers, so a technician calling PostgREST directly still can't break them. The day board is deliberately unpaged (cap 500).
- **0006** `job_date date` + `start_time time` as Hamilton wall-clock values. The server computes "today" (AC-004.8, AC-010.7).
- **0007** Hybrid with no sync in v1; NG-1 designed in the integration contract only.
